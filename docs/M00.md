# M00 — Import Correctness Foundation

## Goal
Stop silently misreporting partial Notion imports as completed, honor CLI
reference switches, and reject untrusted paper storage paths.

## Changes
- The Notion create path no longer retries a validation failure by creating an
  empty page. The original payload error is returned instead.
- Ambiguous network failures on non-idempotent Notion creates/appends are not
  blindly retried. A future reconciliation step (M02) will resolve them.
- Partial block writes, or requested reference subpages that fail, return a
  failed import result including the existing Notion page ID.
- Converters raise on conversion errors instead of returning partial data.
- A conservative recursive Notion block validator checks text, equation,
  child and API batch-size limits before page creation.
- CLI accepts `--from-file` without positional paper IDs, and an explicit
  `--no-refs` overrides JSON import options.
- Paper IDs and categories are validated before file system access.
- Python CI and offline regression tests cover failure-injection scenarios.

## Constraints and known follow-ups
This is **not** exactly-once Notion delivery. A lost response to a successful
remote request is reported as uncertain, and manual reconciliation is still
needed. M02 will add a persistent job checkpoint and read-back reconciliation.

The current text renderer can still truncate text for certain block types;
fix rich-text preservation and block-completeness validation in M01.
Annotation cache invalidation and parse quality are also scoped to M01.
