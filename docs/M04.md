# M04 — Evidence-grounded reading notes and independent review

M04 is built on M03, and deliberately does **not** conflate a source quote
with scientific verification.

## Pipeline
1. Load canonical `document.json` with content hash and node identities.
2. Resolve each LLM paragraph annotation to its exact source Node ID.
3. Check the original text preview, then create one candidate for the
   explanation and one for each key point.
4. Store the source quote, exact character span, section anchor, document
   hash, and a numeric-consistency warning.
5. Export `claim_candidates.json` as **unverified** candidates even if an
   exact source quote is located.
6. Reviewers explicitly record `supported | unsupported | insufficient` in
   an append-only SQLite audit trail. Old verdicts do not survive source
   hash changes.

The source quote is a locator, NOT proof that an LLM interpretation is
logically or empirically supported. No automatic semantic verification is
claimed by this stage.

## Commands

```sh
python -m research.review_cli generate \
  --document papers/ai_agent/1706.03762/document.json \
  --annotations papers/ai_agent/1706.03762/llm_annotations.jsonl \
  --out papers/ai_agent/1706.03762/claim_candidates.json
python -m research.review_cli report --claims path/to/claim_candidates.json
python -m research.review_cli record --claims path/to/claim_candidates.json \
  --document path/to/document.json --claim-id c_... \
  --reviewer "human-reviewer" --verdict supported --notes "Checked source"
python -m research.review_cli export --claims path/to/claim_candidates.json \
  --out reading_report.md
```

Default review database: `./data/reviews.sqlite3`, override `REVIEWS_DB`.
For privacy and audit integrity, do not commit review comments containing
private content into public Git.
